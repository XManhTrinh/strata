# MUI v2 regression fixes — TextField layout, Button icon API, dialog scroll, chip semantics

Four bugs introduced by the MUI v2 API migration are fixed across 27 files. The changes are purely mechanical: no business logic changed. FEAT-001 adds `className="w-full"` to every `<TextField>` in a form or dialog context and removes double-scroll wrappers inside `<DialogContent>`. FEAT-002 moves every `<Icon>` out of `<Button>` children into `leadingIcon`/`trailingIcon` props and converts icon-only buttons to `<IconButton>`. FEAT-003 replaces every display-only `<FilterChip>` with `<AssistChip>` and properly wires the remaining interactive `FilterChip`s with `selected` + `onSelectedChange`. A convergence commit additionally pins `<SnackbarHost>` to `bottom-0` of the viewport, resolving the reported top-of-screen rendering.

Watch for: A cluster of `<Button>` components with direct `<Icon>` children remain in files that were not touched by this diff — confirmed pre-existing in `origin/main`. All four criteria pass for every line the diff actually changed.

**Verdict**: APPROVED

---

## High-level view

All 52 `<TextField>` usages now carry `className="w-full"`, verified by prop-block scan. The criterion is fully met.

The two `<DialogContent>` child wrappers targeted by FEAT-001 (`rate-card-dialog.tsx` and both scroll containers in `csv-import-dialog.tsx`) no longer carry `max-h-*` or `overflow-y-auto`. Remaining `max-h-*/overflow-y-auto` patterns in the codebase sit inside list containers, combo-box dropdowns, and colour-picker swatches — none are immediate `<DialogContent>` children.

Every `<Button>` modified by this diff now uses `leadingIcon`/`trailingIcon` props; no Icon is a direct child of any changed Button. Icon-only buttons in `people/page.tsx` and `assistant-panel.tsx` were converted to `<IconButton>`. Fourteen-plus pre-existing `<Button>/<Icon>` patterns survive in files the diff never touched — they are out of scope here but constitute remaining work.

All display-only `<FilterChip>` usages have been replaced with `<AssistChip>` and `defaultSelected` removed. The sole remaining `FilterChip` usage is in `FlowOrgHeader.tsx`, where team deselect chips are genuinely interactive and correctly wired with `selected={true}` and `onSelectedChange`. Imports are clean: `FilterChip` is imported only where it is used; `AssistChip` and `IconButton` are imported wherever they appear.

The `<SnackbarHost>` now carries `className="fixed inset-x-0 bottom-0 z-50"`. The `z-50` stacking value is lower than typical dialog overlays, so snackbars should not obscure open dialogs.
