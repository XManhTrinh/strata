# Requirements Document

## Introduction

Phase 0 replaces the old monorepo (Next.js + NestJS + Prisma + Redis + BullMQ worker) on the
`rebuild` branch with the foundation for the new Strata: a single Next.js 16 app with Supabase as
the backend, Windmorph for the UI, and the tooling, tests, CI and environments every later phase
depends on. No product features are built in this phase.

Sources: `docs/architecture/0001-tech-stack.md`, `docs/rebuild-plan.md` (sections 1, 4 and 5).

## Glossary

- **App**: the new Next.js 16 application at the repository root.
- **Local_Stack**: the Supabase stack started with `supabase start`.
- **Migration**: a SQL file in `supabase/migrations`.
- **Database_Types**: `src/lib/supabase/database.types.ts`, generated by `supabase gen types`.
- **CI**: the GitHub Actions workflows in `.github/workflows`.
- **Staging** / **Production**: the Supabase projects and Vercel environments of those names.

## Requirements

### Requirement 1: Remove the old system from the branch

**User Story:** As a developer, I want the branch to contain only the new system, so that nobody
(and no AI tool) builds on the old architecture by mistake.

#### Acceptance Criteria

1. THE branch SHALL NOT contain `apps/`, `packages/`, `turbo.json`, `render.yaml`,
   `Dockerfile.api`, `Dockerfile.worker` or `docker-compose.yml`.
2. THE branch SHALL keep `sample-data/` as reference input for import tests.
3. THE `.gitignore` SHALL ignore `next-env.d.ts`, `.env*` (except `.env.example`), `.next`,
   `coverage`, `playwright-report`, `test-results` and `supabase/.temp`.
4. THE old code SHALL remain available on `main` for reference.

### Requirement 2: Application scaffold

**User Story:** As a developer, I want a correctly configured Next.js app, so that features can be
added without revisiting the setup.

#### Acceptance Criteria

1. THE App SHALL use Next.js 16 App Router, React 19 and TypeScript in strict mode at the
   repository root, managed with pnpm.
2. THE App SHALL resolve `@/*` to `src/*`.
3. THE App SHALL follow the folder structure in `.kiro/steering/structure.md`.
4. THE App SHALL expose the scripts `dev`, `build`, `start`, `lint`, `typecheck`, `format`,
   `test`, `test:e2e`, `db:test`, `db:types`.
5. WHEN `pnpm build` runs with valid environment variables, THE App SHALL build without errors or
   warnings from type checking or linting.
6. THE App SHALL install every dependency at its **latest stable version** at the time of the
   scaffold, keeping pnpm's minimum release age for supply-chain safety; no version is copied from
   the old `package.json` files.
7. THE App SHALL contain **only dependencies it uses**. Nothing from the old system is carried
   over by default; at least `@dnd-kit/*`, `@strata/*`, `zustand`, NestJS, Prisma, `ioredis`,
   `bullmq`, `bcrypt`, `jose`, `uuid`, `dotenv`, `express` and `turbo` are gone, and
   `pnpm-workspace.yaml` lists build permissions only for packages that are installed.

### Requirement 3: Windmorph theme and base layout

**User Story:** As a user, I want a consistent Material 3 look in light and dark mode from the
first screen.

#### Acceptance Criteria

1. THE App SHALL install `@windmorph/react` and `@windmorph/react-pro` and import their styles in
   `globals.css` in that order, with an `@source` line for each.
2. THE App SHALL wrap the root layout in Windmorph's `ThemeProvider` using the baseline theme, and
   SHALL read the theme from cookies on the server so the first render has the right mode.
3. THE App SHALL load Material Symbols and provide one `Icon` component.
4. The shared Snackbar host and the reduced-motion aware motion helper SHALL be added with their
   first use (the Phase 1 shell), because the App contains only code it uses.
5. THE App SHALL render a placeholder home page using only Windmorph components and tokens.

### Requirement 4: Translation layer

**User Story:** As a product owner, I want all text translatable from day one, so that new
languages need no screen rewrites.

#### Acceptance Criteria

1. THE App SHALL use `next-intl` with English (`en`) as the only locale and no locale prefix in
   URLs.
2. THE App SHALL load all UI text from `src/messages/en.json`.
3. THE App SHALL format dates and numbers through `next-intl` using the user's locale.
4. THE lint configuration SHALL flag string literals rendered as JSX text.

### Requirement 5: Supabase project, migrations and types

**User Story:** As a developer, I want the database defined only by migrations, with generated
types, so that the schema is reviewable and reproducible.

#### Acceptance Criteria

1. THE repository SHALL contain `supabase/config.toml` configured for Strata (site URL, redirect
   URLs, email confirmations on, minimum password length 8, Google provider placeholders).
2. THE first Migration SHALL enable the `ltree`, `pg_cron` and `pgmq` extensions and create the
   shared helpers: `set_updated_at()` trigger function and an `app` schema for permission
   functions. `pgtap` SHALL be enabled inside the test files only, so it never reaches production.
3. WHEN `pnpm db:types` runs against the Local_Stack, THE Database_Types SHALL be regenerated.
4. THE App SHALL provide the proxy Supabase client in `src/lib/supabase`, typed with
   Database_Types. The server and browser clients SHALL be added with their first use in Phase 1.
5. THE proxy (`src/proxy.ts`) SHALL refresh the session on every request and verify it with
   `getClaims()`.
6. THE repository SHALL contain `.env.example` listing every variable, without real values.

### Requirement 6: Code quality tooling

**User Story:** As a developer, I want automatic checks, so that code stays consistent.

#### Acceptance Criteria

1. THE App SHALL use ESLint flat config with `eslint-config-next`, TypeScript rules
   (`no-explicit-any` as error) and `jsx-a11y`.
2. THE App SHALL use Prettier with the repository's existing settings.
3. WHEN `pnpm typecheck` runs, THE App SHALL type-check without emitting files.
4. THE App SHALL run `knip` to report unused dependencies, files and exports, and CI SHALL fail
   when it finds any.
5. THE repository SHALL use Renovate to open grouped weekly update pull requests, so dependencies
   stay current.

### Requirement 7: Test infrastructure

**User Story:** As a developer, I want every test level working before features exist.

#### Acceptance Criteria

1. THE App SHALL run unit tests with Vitest, including one example test.
2. THE App SHALL run end-to-end tests with Playwright at phone (390px), tablet (834px) and desktop
   (1440px) widths, including one smoke test of the home page with an axe accessibility check.
3. THE repository SHALL run pgTAP tests with `supabase test db`, including one test asserting
   that RLS is enabled on every table in the `public` schema.

### Requirement 8: Continuous integration

**User Story:** As a developer, I want every push checked automatically.

#### Acceptance Criteria

1. WHEN code is pushed or a pull request is opened, CI SHALL run lint, typecheck, `knip`, unit tests,
   database tests against a Local_Stack, the end-to-end smoke test and a Database_Types drift
   check.
2. IF the generated Database_Types differ from the committed file, THEN CI SHALL fail.
3. CI SHALL install `@windmorph/react-pro` using a read-only token stored as a repository secret.
4. WHEN a change is merged to the release branch, CI SHALL apply new Migrations to Staging.

### Requirement 9: Environments and monitoring

**User Story:** As a product owner, I want staging and production ready, in the EU.

#### Acceptance Criteria

1. Staging and Production SHALL each have a Supabase project in the Frankfurt region.
2. THE Vercel project SHALL run server code in Frankfurt and have preview, staging and production
   environments with their own variables.
3. THE App SHALL report errors to Sentry with EU data storage from browser, server and Edge
   Functions, without sending personal data.

### Requirement 10: Developer guidance

**User Story:** As a developer using Kiro or Claude Code, I want the tools to know the plan.

#### Acceptance Criteria

1. THE `.kiro/steering` files SHALL describe the product, stack, structure, UI, database and test
   rules of the rebuild.
2. THE repository SHALL contain a `CLAUDE.md` pointing to the same steering files and `docs/`.
3. THE `README.md` SHALL explain local setup: prerequisites, `supabase start`, environment
   variables, the private Windmorph Pro token, and the main scripts.
